# 对话创作与直接执行的边界

## 本轮修复

- 排版预览、导出、素材准备、草稿保存直接执行原有 CLI 操作。宿主确认只包围 approval.request；确认结束后 CLI 执行，不占用模型轮次。宿主仍要求授权审计处于一个短暂轮次，因此授权记录不会完全从对话消失，不能声称彻底零轮次。
- 新增「检查发布条件」调用真实 md2wechat inspect --draft。检查结果以结构化数据回到页面，转换成简短中文说明，不暴露本地路径。检查结果在轮询中保留，文章版本改变后失效。
- 标题、润色、图片请求继续由当前会话生成，通过现有带文章、版本和请求标识的工具回填。过期回填仍被拒绝。
- 选择封面保留已生成的正文预览，同时撤销最终素材和审阅资格；不再次调用排版。
- 保存面板列出正文、标题、封面、预览及功能配置缺项。普通执行和创作请求有不同状态说明。
- 生成请求超过两分钟不再静默停止结果轮询，增加等待提示与手动刷新入口。

## 验证

类型、构建、静态检查和 805 项测试通过。安装包边界检查通过。真实 DSH 0.2.1-rc.2 与 CLI 3.8.0 的隔离模拟流程验证授权、预览、导出、草稿保存和重启恢复，以及无需模型的 CLI 检查。浏览器实查发现检查结果被轮询清除，修复后复测。

真实公众号及付费生图未在本轮调用；检查通过不等于公众号凭据已验证。当前宿主仍要求授权时对话空闲，这一限制没有被绕过。工作区原有 dist/ 旧安装包保留未动，不加入本轮改动。未修改已发布标签。

## 用户反馈后的修正
页面预览不再使用授权轮次：用户点击即直接执行 CLI。模型调用的预览工具仍保留默认授权。图片请求先执行 CLI 无副作用规划，再携带规划交给当前会话；标题原本已使用 CLI 准备请求。
实际机器的 CLI 已有排版密钥，但 DSH 凭据未连接；仅将现有排版密钥接入 DSH 受保护存储，未复制微信和生图凭据。标准安装默认引用 MD2WECHAT_API_KEY，显式空映射仍尊重。重启本地 DSH 后已用用户当前文章检查真实排版成功，预览没有新审批或模型轮次。

最终验证：806 项测试通过；隔离验收明确断言页面预览不新增审批、对话轮次或模型请求。用户当前文章的正式排版已实际显示。图片规划已通过 CLI 无副作用计划命令验证，未执行付费图片生成。
